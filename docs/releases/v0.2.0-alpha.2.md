# v0.2.0-alpha.2 — hardened alpha with WhatsApp and admin operations

Release decision: **alpha endurecida, no GA**. Esta versión amplía las capacidades de canal e interacción operativa de `v0.2.0-alpha.1`, pasando la totalidad de los 17 gates de calidad WCT y la suite de evaluación determinista. Es apta para despliegues controlados de operador único tras el paso de la PR protegida. No está aprobada para disponibilidad general ni servicios desatendidos multi-inquilino.

## Highlights

- **WhatsApp Inbound & Outbound**:
  - Webhook de entrada (`GET /webhook/whatsapp` y `POST /webhook/whatsapp`) con verificación de firma criptográfica HMAC SHA-256 (`X-Hub-Signature-256`) y validación de tokens de challenge de Meta.
  - Respuestas automáticas inmediatas a mensajes entrantes de usuarios autorizados (`WHATSAPP_ALLOWED_USER_IDS`) mediante WhatsApp Graph API (`sent=true`), con emisión segura de grants P5 en servidor.
  - Enrutamiento multicanal (`ChannelNotificationRouter`) para entrega proactiva de recordatorios agendados tanto por Telegram como por WhatsApp.
- **Panel de Administración y Operaciones P5**:
  - Vistas administrativas loopback-only (`GET /admin/dashboard` y `GET /admin/events`) autenticadas por Bearer token.
  - Aprobación y denegación explícita de acciones pendientes de alta sensibilidad (tier P5).
  - Reconciliación de entregas ambiguas (`uncertain`) con resolución a `delivered` o `retry` preservando confidencialidad y sin filtrar datos sensibles en logs.
- **Arquitectura y Gobernanza Estricta (WCT)**:
  - Adopción integral de los 17 quality gates de WCT (`G-META-1/2`, `G-RULES-DRIFT`, `G-SUPPRESS`, `G-DEBT`, `G-LINT`, `G-FMT`, `G-TYPE`, `G-TEST`, `G-ARCH`, `G-ARCHMETRICS`, `G-DEPS`, `G-DEAD`, `G-SAST-BANDIT`, `G-SECRET`, `G-MUT-SITES`, `G-ACCEPT`).
  - Modularización limpia bajo el presupuesto de ≤100 mutation sites por archivo (`http.py`, `worker.py`, `reminder_notifications.py`, `whatsapp.py`).
  - Allowlist estricto de egress saliente con soporte para Graph API (`graph.facebook.com`).

## Database change

No se introducen migraciones de base de datos nuevas respecto a `v0.2.0-alpha.1`. La base de datos permanece en el esquema `0005_worker_heartbeat.sql` (migraciones `0001` a `0005`).
La entrega por WhatsApp y las operaciones administrativas operan sobre el esquema durable existente (`assistant_outbox`, `assistant_scheduler_events`, `assistant_worker_heartbeats`).

## Compatibility and known gaps

- **Endpoint de salud `/healthz`**:
  - Sigue disponible como alias de compatibilidad deprecado hacia `/livez`, emitiendo headers `Deprecation: true` y `Link: </livez>; rel="successor-version"`.
- **Canal WhatsApp**:
  - Soporta texto puro y entregas proactivas; no admite transcripción de notas de voz ni procesamiento de archivos multimedia entrantes.
- **Acceso Administrativo**:
  - El panel y endpoints `/admin/*` permanecen restringidos a interfaces loopback (`127.0.0.1` / `::1`).
- **Worker de Entregas**:
  - El worker durable requiere PostgreSQL para la coordinación atómica con `SKIP LOCKED`.
- **Reconciliación de entregas `uncertain`**:
  - Los fallos ambiguos de red o caídas durante la llamada al proveedor se marcan como `uncertain` sin filtrar contenido confidencial del mensaje, requiriendo resolución manual del operador.
