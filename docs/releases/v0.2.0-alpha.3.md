# v0.2.0-alpha.3 — hardened alpha with remote admin access and WCT v2 governance

Release decision: **alpha endurecida, no GA**. Esta versión consolida el endurecimiento del pipeline de gobernanza y abre el panel administrativo a acceso remoto controlado (opt-in, desactivado por defecto). Pasa la totalidad de los 17 gates de calidad WCT y la suite de evaluación determinista. Es apta para despliegues controlados de operador único tras el paso de la PR protegida. No está aprobada para disponibilidad general ni servicios desatendidos multi-inquilino.

## Highlights

- **Acceso remoto al panel administrativo (fase 22)**:
  - Nuevo flag `ADMIN_ALLOW_REMOTE` (default `False`): sin él, `/admin/*` sigue restringido a loopback (`127.0.0.1` / `::1`), sin cambio de comportamiento para despliegues existentes.
  - Login de navegador con cookie de sesión: `POST /admin/login` (form `application/x-www-form-urlencoded`) fija `admin_token` con `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/admin`, `Max-Age=43200`; `POST /admin/logout` la revoca.
  - Guardarraíl de arranque: con acceso remoto activo, la app exige `ADMIN_TOKEN` de al menos 32 caracteres o levanta `RuntimeError`.
  - Uso documentado exclusivamente detrás de túnel TLS o reverse proxy, con procedimiento de rotación de tokens.
- **WCT harness v2 — sync con el template (fase 23)**:
  - Huellas de mutación posicionalmente independientes (hash por AST semántico, manifiesto schema 2): mover código o añadir imports ya no invalida el manifiesto.
  - `wct mutate update-manifest` atómico: regenera el manifiesto y el `integrity.lock` en un solo paso aprobado, con evidencia obligatoria (URL o `#N`) en `--reason`.
  - Hashes de integridad EOL-normalizados (`sha256:eol-normalized`): fin del drift por finales de línea.
  - Nuevo comando `wct fmt --staged`: formateo restringido al changeset, para adopciones graduales sin tocar archivos legacy ajenos.
  - Diagnósticos enriquecidos de colisión `placeholder-variant` en G-ACCEPT y detección anti-evasión de imports dinámicos en G-ARCHMETRICS.
  - 60 tests del harness portados al repo (hooks, integridad, mutación, fmt, secrets, archmetrics, accept).
- **Endurecimiento del pipeline de release (fases 20-21)**:
  - Fuente única de versión: `personal_assistant.__version__` se deriva de la metadata del paquete instalado.
  - El job `quality` de CI ejecuta `wct integrity check` sobre las rutas protegidas; el check tolera con advertencia rutas protegidas no rastreadas ausentes.
- **Higiene operativa (fases 19 y 24)**:
  - Actualización de dependencias de desarrollo (ruff, diff-cover, import-linter, coverage, pyyaml) manteniendo cero CVEs críticos/altos.
  - Flake del sweeper concurrente eliminado (presupuesto de reintentos por contención con micro-backoff; 20/20 corridas verdes contra PostgreSQL real).
  - Guard de `Content-Length` en `POST /admin/login`: cuerpos > 4096 bytes reciben `413` estructurado sin leer el cuerpo ni emitir cookie.
  - Eliminada la indirección de `compare_digest` vía `sys.modules`; verificación de token en tiempo constante directa con `hmac.compare_digest`.
- **Documentación de producto**:
  - README reescrito como portada profesional del producto con enlaces a arquitectura, runbooks y gobernanza.

## Compatibility and known gaps

- **Endpoint de salud `/healthz`**:
  - Sigue disponible como alias de compatibilidad deprecado hacia `/livez`, emitiendo headers `Deprecation: true` y `Link: </livez>; rel="successor-version"`.
- **Canal WhatsApp**:
  - Soporta texto puro y entregas proactivas; no admite transcripción de notas de voz ni procesamiento de archivos multimedia entrantes (planificado como siguiente fase).
- **Acceso Administrativo**:
  - Por defecto, el panel y endpoints `/admin/*` permanecen restringidos a loopback (`127.0.0.1` / `::1`).
  - Con `ADMIN_ALLOW_REMOTE=true`, el acceso remoto queda habilitado exclusivamente detrás de un terminador TLS (túnel o reverse proxy) y exige `ADMIN_TOKEN` de al menos 32 caracteres; el guardarraíl de arranque bloquea configuraciones débiles.
- **Worker de Entregas**:
  - El worker durable requiere PostgreSQL para la coordinación atómica con `SKIP LOCKED`.
- **Reconciliación de entregas `uncertain`**:
  - Los fallos ambiguos de red o caídas durante la llamada al proveedor se marcan como `uncertain` sin filtrar contenido confidencial del mensaje, requiriendo resolución manual del operador.
- **Gobernanza WCT**:
  - El manifiesto de mutación migra a schema 2; los manifiestos schema 1 se regeneran con `wct mutate update-manifest --approved-by ... --reason ...` (atómico con el bless de integridad).
