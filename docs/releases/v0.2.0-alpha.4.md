# v0.2.0-alpha.4 — hardened alpha with WhatsApp voice intake and WCT v3 PR-tier governance

Release decision: **alpha endurecida, no GA**. Esta versión convierte las notas de voz de WhatsApp en ciudadanos de primera clase del pipeline de conversación y eleva la gobernanza local a paridad con CI (tier `pr` de WCT con cobertura diferencial). Pasa los 21 gates del tier `pr` de WCT (incluyendo G-COV-DIFF, G-HOOKS-WIRED y G-REDTEAM) y la suite de evaluación determinista. Es apta para despliegues controlados de operador único tras el paso de la PR protegida. No está aprobada para disponibilidad general ni servicios desatendidos multi-inquilino.

## Highlights

- **WhatsApp media entrante (fase 25)**:
  - Mensajes de `audio` y notas de `voice` se descargan de la Graph API de Meta (`GET /{media-id}` + descarga autenticada), se transcriben con el proveedor configurable (`TRANSCRIPTION_PROVIDER`, compatible OpenAI/Groq) y el transcript entra al pipeline de conversación como si fuera texto: extracción de recordatorios, idempotencia por `wamid`, replies y traces.
  - Seguridad: el orden de chequeos es innegociable — firma HMAC → allowlist de remitente (403) → solo entonces red. Redirects de Meta (`lookaside.fbsbx.com`) seguidos manualmente validando cada hop contra la egress allowlist (fail-closed). Tope de 20 MB validado antes (tamaño declarado) y después (bytes descargados) de la descarga. Los binarios nunca se persisten; los traces guardan metadatos + transcript truncado a 500 chars.
  - Medios no soportados (`image`, `document`, `video`) reciben respuesta explícita `whatsapp_media_unsupported` — nunca un no-op silencioso.
  - 8 escenarios Gherkin nuevos en `features/whatsapp_inbound_webhook.feature` con tests de comportamiento; diff-coverage del cambio: 100% (190/190 líneas).
- **WCT harness v3 — tier `pr` con paridad CI (fase 26)**:
  - Nuevo tier `pr` (21 gates): todo el tier `commit` + `G-HOOKS-WIRED` + `G-COV-TOTAL` + `G-COV-DIFF` + `G-REDTEAM`. `G-COV-DIFF` ejecuta `diff-cover --compare-branch <base> --fail-under 90` en local — la verificación que antes solo existía en CI (cerrando el hueco detectado en la fase 25).
  - Preflight `G-ENV`: cada tier puede declarar variables de entorno requeridas en `governance/policy.yaml` (`environment_required`); si falta alguna, el tier falla antes de correr gates nombrando la variable — fin de los skips silenciosos.
  - Nuevo comando `wct split-plan <archivo>`: propone la partición fachada de archivos que exceden el presupuesto de sitios de mutación (TEST-007), con imports de re-exportación sugeridos.
  - Diagnósticos enriquecidos: G-MUT-SITES explica cuándo el manifiesto es legacy/ausente; las colisiones `placeholder-variant` de G-ACCEPT sugieren la reformulación nombrando el Scenario Outline.
  - `wct ratchet record` exige evidencia (URL o `#N`) en `--reason`, igualando el contrato del bless de integridad.
- **Seguridad de dependencias**:
  - `pip` 26.1.2 → 26.2.1 resolviendo `PYSEC-2026-3721` (detectado por el gate G-CVE en CI).

## Compatibility and known gaps

- **Endpoint de salud `/healthz`**:
  - Sigue disponible como alias de compatibilidad deprecado hacia `/livez`, emitiendo headers `Deprecation: true` y `Link: </livez>; rel="successor-version"`.
- **Canal WhatsApp**:
  - Soporta texto, notas de voz/audio con transcripción y entregas proactivas. No procesa imágenes, documentos ni video (respuesta explícita de no soportado; la extracción de contenido de imágenes/documentos requiere un puerto de visión/OCR que no existe aún).
  - La descarga de media requiere `WHATSAPP_ACCESS_TOKEN`; sin proveedor de transcripción configurado, el usuario recibe una respuesta explícita.
- **Acceso Administrativo**:
  - Por defecto, el panel y endpoints `/admin/*` permanecen restringidos a loopback. Con `ADMIN_ALLOW_REMOTE=true`, el acceso remoto exige túnel TLS o reverse proxy y `ADMIN_TOKEN` de al menos 32 caracteres (guardarraíl de arranque).
- **Worker de Entregas**:
  - El worker durable requiere PostgreSQL para la coordinación atómica con `SKIP LOCKED`.
- **Reconciliación de entregas `uncertain`**:
  - Los fallos ambiguos se marcan como `uncertain` sin filtrar contenido confidencial, requiriendo resolución manual del operador.
- **Gobernanza WCT**:
  - El tier `pr` es la verificación recomendada pre-PR: `uv run python -m tools.wct gate --tier pr` (requiere `TEST_POSTGRES_DSN` exportado — G-ENV lo exige). La paridad de G-COV-DIFF local vs CI es aproximada (rama vs línea); CI sigue siendo la autoridad.
