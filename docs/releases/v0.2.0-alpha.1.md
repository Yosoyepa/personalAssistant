# v0.2.0-alpha.1 — hardened alpha

Release decision: **alpha endurecida, no GA**. This version is suitable for a
controlled, single-operator deployment after the documented gates pass. It is
not approved for general availability or an unattended multi-tenant service.

## Highlights

- Adds dependency-free `GET /livez` and truthful `GET /readyz` checks for
  PostgreSQL access, current migrations, and a fresh delivery-worker heartbeat
  when the worker is enabled.
- Keeps `GET /healthz` as a deprecated alias of `/livez` for this version. The
  response carries `Deprecation: true` and a successor link.
- Persists one cross-process worker heartbeat containing only a fixed component
  name and timestamp. It contains no PID, host, tenant, recipient, body, or
  message identifier.
- Adds authenticated, loopback-only `GET /admin/metrics`. Its closed response
  contains only `pending`, `claimed`, `sending`, `published`, `failed`, and
  `uncertain` counts plus operational health states.
- Makes all 293 deterministic eval cases a blocking CI check on PostgreSQL 16
  with Telegram, LLM, transcription, and TTS providers disabled.
- On the local Windows/PostgreSQL 16.14 acceptance environment, the exact CI
  eval command completed 293/293 cases in 75.522 seconds. The authoritative
  hosted gate and its execution evidence are retained in GitHub Actions on the
  release PR.
- Adds adversarial PII, stale/missing/future heartbeat, fake-clock, migration,
  and cross-connection heartbeat tests.

## Database change

Migration `0005_worker_heartbeat.sql` creates
`assistant_worker_heartbeats`. Apply it before starting this version. Runtime
startup never applies DDL, and `/readyz` remains HTTP 503 while a migration is
pending.

## Compatibility and known gaps

- `/healthz` remains available only as a one-version compatibility alias;
  probes should move to `/livez` now.
- The worker remains PostgreSQL- and Telegram-only. `uncertain` delivery
  outcomes still require explicit operator reconciliation.
- Context-utilization measurement, long-session compaction, sandboxed tool
  execution, calibrated LLM judges, and complete production trace retention are
  not implemented. See the production-readiness audit.

Release publication and the controlled bot acceptance smoke are performed by
the release owner after the offline gates pass; preparation never embeds or
prints provider credentials.
